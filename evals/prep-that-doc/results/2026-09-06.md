## Paired Document Exercise

Two independent Codex CLI runs used GPT-5.6 Sol with medium reasoning. Each received the same clean README and incident runbook, plus the same editing request. One run loaded the supplied skill snapshot; the other used its ordinary editing workflow. The author could not provide missing operational facts. Neither run was authorized to execute the procedure or contact anyone.

| Observed result | With skill | Without skill |
| --- | --- | --- |
| Clean README | Byte-identical | Reworded |
| Runbook structure | Four heading promotions | Steps split and renumbered, recovery substeps introduced |
| Non-heading runbook lines | Identical | Different |
| Unspecified duration | Preserved and reported as a question | Sentence deleted; no duration question |
| Completed shell commands | 12 | 3 |
| Scanner invocations | 3 | 0 |

Direct comparison with separately retained originals verifies the with-skill artifact. It preserves commands, step identifiers, order, thresholds, caveats, and unresolved facts. The run scanned each file initially and only the edited runbook afterward. It loaded the workflow, element, and prose references, without loading roast guidance or scanner implementation.

The skill run attempted to reconstruct the original for a diff instead of retaining a real original. That is a verification weakness even though independent comparison confirms the resulting artifact. The candidate's verification instruction explicitly requires the real original or a real version-control diff. That clarification and subsequent parser corrections are covered by source review and regression checks, not by a repeat of this live exercise.

## Brief Validation Decisions

- Roast remains an optional, separately loaded reference within the existing skill. A second installation is unnecessary for an existing mode.
- Migration, security, and risk-assessment profiles make the promised safeguards explicitly selectable.
- Rule overrides remain user-controlled. Scanner policy does not grant permission to edit protected facts or procedures.
- An uneven table body row is not automatically malformed. [GitHub Flavored Markdown permits varying body cell counts](https://github.github.com/gfm/#tables-extension-).
- Protected-region parsing covers the documented forms; it is not represented as a complete Markdown renderer.
- The scanner reports candidates and never edits. Contextual rules and missing facts stay in the agent's classification workflow.

The scanner exit contract requires callers to handle 0 for no visible candidates, 1 for candidates, and 2 for execution or input errors. A quiet default scan omits LOW findings. Neither exit 0 nor a lower candidate count proves document quality.
