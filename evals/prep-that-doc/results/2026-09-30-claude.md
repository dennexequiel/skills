# Prep That Doc Claude Model Comparison

Both skill versions preserve the operational timing expectation in all eight Claude runbook outputs. This is a stronger observed preservation result than the smaller-model sample, but it does not establish that the updated skill is consistently better. Reviews still show excess reporting, unnecessary blockers, and unsupported editorial claims.

Sonnet completes all 16 scored trials. Opus completes 14 within the three-minute limit. One timed-out Opus trial has no report and removes the final newline; the other saves its review but does not return a terminal response. Both remain in the results.

## Method

The comparison uses 32 fresh Claude Code processes: two models, four fixtures, two skill versions, and two repetitions. Claude Code 2.1.277 resolves `opus[1m]` to `claude-opus-5[1m]` and `sonnet[1m]` to `claude-sonnet-5[1m]`. Both request `xhigh` effort, with a 180-second limit and a $2 client-estimate limit per trial. No CLI update or model substitution is performed.

The previous snapshot comes from commit `cb82094358db54c4a1342c5a3c1829ee06351dec`; the updated snapshot is the uncommitted revision under review. Inputs and full skill snapshots match the [Luna comparison](2026-09-30-luna.md). Hash checks confirm that the skill snapshots remain intact and the repository skill matches the evaluated candidate.

Each worker gets an isolated workspace and explicit skill path. Safe mode disables personal and project customizations. File tools are restricted, integrations are disabled, and shell permissions use an explicit scanner and file-inspection allowlist. Some compound commands are denied. These denials remain visible as harness limitations, including a skipped scanner pass after a denied runtime check.

Setup attempts are excluded before scoring. These include authentication and permission probes, plus eight attempts affected by an unapplied allowlist correction. Those processes are stopped on discovery and their recorded actions show local fixture work. The inspected allowlist stays fixed for scored runs; no scored timeout or weak outcome is retried. The [measurement record](2026-09-30-claude.json) preserves these incidents separately from scored outcomes, along with prompts, hashes, artifacts, reports, sanitized tool traces, accounting, and grades.

## Findings

- All eight typo-edit artifacts contain only the requested correction. Their reports are disproportionate: Opus writes 204-306 words and Sonnet 118-152 words for this one-character edit.
- All eight runbooks preserve the vague duration sentence, commands, ordering, numeric thresholds, and warnings. The clean README stays unchanged. Some reports treat an acknowledged operational gap as something that needs no further question, or mark completed editorial work as blocked.
- All eight spacing artifacts preserve the fenced body bytes, tight list, table values, and valid reference-style link. Seven retain exactly one final newline; the timed-out previous-skill Opus output has none. Scanner results alone do not detect this failure.
- All eight evidence reviews leave the source files unchanged and show the correct multiplications: 120 times 4 equals 480, and 4 times $0.10 times 720 equals $288. This verifies arithmetic against supplied fixture inputs, not real throughput, pricing, or linear scaling.
- An updated Opus review asserts that the load-test and pricing attachments are absent from the destination because the receipt names only `capacity.md`. The receipt cannot establish that. Another updated Opus review says a success response establishes that a transfer occurred. Both statements overreach the available local evidence.
- The second updated Sonnet evidence review identifies undefined `N`/`mu`, preserves the stated scaling qualification, and treats missing owner or approver names as optional context. The first repetition treats names as an author gap and misses the notation. The behavior is not consistent across two trials.

The numeric rubric underweights concision, unjustified blockers, and unsupported editorial claims. A high score does not resolve those weaknesses. The evidence supports follow-up work on proportional reporting and disciplined use of receipts, without making every short edit a research or publishing task.

## Verification And Limits

- **Mechanical:** Input/output comparisons, skill hashes, and independent post-run scanner results are recorded. Worker scanner execution and denied calls are checked from tool traces separately. `bun run check` passes: 115 tests, 765 assertions, plus type, bundle, routing, catalog, and generated-rule checks.
- **Editorial:** Blind review compares each artifact and report against its purpose and the fixed rubric. Grades remain unchanged after identities are revealed. Literal formatting differences are distinguished from operational meaning loss.
- **Factual:** Fixture arithmetic is independently checked. Real measurements, prices, and scaling behavior are not verified. Recorded worker tools show no operational procedure or network action; two attempted writes to temporary paths outside a trial workspace are denied.
- **Rendering and delivery:** Not verified. No destination renderer, remote read-back, real upload, or export is exercised. The supplied receipt is synthetic. Roast mode and the complete behavioral scenario suite are outside this comparison.

Two repetitions per case provide a failure probe, not a reliability estimate. Luna uses a different runtime and inherited context, so cross-model differences cannot be attributed solely to the model. Claude's reported costs are client estimates, not subscription billing; two timed-out trials lack final cost records. Concurrency, cache state, tool choices, and denied commands also affect runtime and cost.
